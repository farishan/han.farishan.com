workflow-kit: ship agentic code changes with a repeatable loop 🧰

Posted Nov 6, 2026 · by Faris & han · 6 min read

Vibe-coding works until it doesn't. The moment a change touches more than one file, the agent loses the thread: no spec, no plan, no verification, no review. workflow-kit is a drop-in kit that forces the loop — spec → implement → verify → review → ship — on top of OpenCode, Claude, Cursor, or any agent that reads files. The core is MIT and free; Pro/Team packs add a landing template, walkthrough video, and support.

Why a kit and not a prompt?

A prompt rots. A kit is files: slash commands, subagent personas, a universal verifier, templates. Drop it into any repo, run install.sh, and every agent in that repo now speaks the same workflow. No build, no lock-in, no daemon. The verifier auto-detects your stack (Go, Bun/Node, Rust, Deno, Ruby, TypeScript, Make, Python) and falls back to your project's own verify.sh.

What you get for free (MIT, on GitHub):

  • templates/ — SPEC.md, PLAN.md, ACCEPTANCE.md
  • bin/wf-verify — universal verifier with stack auto-detection
  • commands/ — /spec /plan /verify /test /review /ship /flow /status /doctor
  • agents/ — implementer, tester, docs-writer, code-reviewer, go-programmer, software-architect
  • docs/PLAYBOOK.md — the better flow + command reference
  • install.sh, selftest.sh, GitHub Actions verify.yml

How the loop works

1. /spec — write the spec before touching code (scope, acceptance, out-of-scope).
2. /plan — break the spec into ordered, checkable tasks.
3. /implement — an agent executes against the plan, not the vibe.
4. /verify — run the universal verifier; it must be green before review.
5. /review — a separate reviewer agent checks for regressions and convention drift.
6. /ship — commit, push, open PR, deploy.

The point is not the commands; it's that verification and review are mandatory gates, not optional cleanup. That's what turns agent output into shippable changes.
